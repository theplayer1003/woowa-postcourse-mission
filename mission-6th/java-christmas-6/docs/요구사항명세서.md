# 크리스마스

## 시나리오

1. 애플리케이션 실행
2. 앱 컨픽
    1. 의존성 주입
    2. 데이터 이니셜라이저가 도메인이니셜라이저에게 메뉴 레포지토리를 주며 초기화 요청
3. 인트로 안내 프롬프트 출력
4. InputView 에게 사용자 입력을 받도록 요청
    1. 날짜
    2. 숫자인지 검증해서 반환
5. 사용자 입력 요청
    1. 메뉴와 개수 문자열 반환
6. 컨트롤러가 리퀘스트 디티오 작성
7. 컨트롤러가 서비스한테 리퀘스트 넘겨주면서 요청
    1. 서비스는 리퀘스트를 받음
    2. 서비스는 리퀘스트를 오더 팩토리한테 리퀘스트를 던지고 오더 생성 요청
        1. 오더 팩토리는 리퀘스트의 숫자로 방문날짜 생성
        2. 오더 팩토리는 리퀘스트의 string을 오더 파서한테 파싱 요청
            1. 오더 파서는 String 을 trim 후 , 로 스플릿하고 - 로 스플릿해서 String, Int map을 만듬, 숫자는 숫자 맞는지 파스인트 하면서 검증
        3. 오더 팩토리는 반환받은 맵으로 메뉴 레포에 메뉴 엔티티를 요청함
            1. 레포는 이름으로 메뉴를 찾아 반환함
                1. 메뉴는 메뉴 타입, 이름, 가격 으로 구성됨
        4. 오더 팩토리는 메뉴를 받아서 주문수와 함께 오더 아이템을 만듬
        5. 오더 팩토리는 오더 아이템들을 모아 오더 아이템즈를 만듬
        6. 오더 팩토리는 오더 아이템즈와 방문날짜로 오더 객체를 만듬
    3. 서비스는 이벤트 매니저한테 오더를 넘겨주고 혜택 모음 생성 요청
        1. 이벤트 매니저는 이벤트 정책을 순회하면서 오더를 넘겨주고 이벤트 조건을 검사
            1. 이벤트 정책들은 오더에게 필요한 조건들의 검사를 시키고 결과를 조합해 참 거짓을 판단
        2. 이벤트 매니저는 조건이 참일 시 오더를 넘겨주고 혜택 결과 객체 생성 요청
            1. 이벤트 정책들은 오더에게 알맞은 정보를 요청해서 혜택 결과를 생성, 반환
        3. 이벤트 매니저는 혜택들을 모아서 혜택 모음 생성 후 반환
    4. 서비스는 매퍼에게 혜택 모음 객체를 넘겨주고 dto 생성을 요청, 반환
8. 컨트롤러는 dto를 아웃풋 뷰에게 넘겨주고 출력 요청
9. 끝

# 1. Domain Layer

## A. 메뉴
- `Menu`: 메뉴 하나의 정보를 가진 엔티티
    - 필드
        - `MenuType`: Enum
        - `String menuName`
        - `Integer price`
    - 메서드
        - `boolean isType(MenuType target)`
- `VisitDate`: 주문 날짜에 관련된 로직을 처리
    - `boolean isDdayPeriod()`
    - `boolean isWeekdaysPeriod()`
    - `boolean isWeekendPeriod()`
    - `boolean isSpecialdayPeriod()`
- `OrderItem`: 주문 메뉴와 수량
    - 필드
        - `Menu menu`
        - `Int quantity`
    - 메서드
        - `boolean isMenuType(MenuType type)`
- `OrderItems`: `OrderItem`의 일급 컬렉션
    -  필드
        - `List<OrderItem> orderItems`
    - 메서드
        - `boolean hasMenuType(MenuType type)`
        - `int countByMenuType(MenuType type)`
- `Order`
    - 필드
        - `OrderItems`
        - `VisitDate`
    - 메서드
        - `boolean isWeekday()`
        - `boolean hasMenuType(MenuType type)`
        - `int countMenuType(MenuType type)`
- `OrderFactory`: `Order` 객체를 생성할 책임
    - 메서드
        - 사용자 입력 주문 맵을 통해 `MenuRepository` 로부터 알맞은 메뉴를 꺼내온다
        - 수량과 함께 `OrderItem` 을 생성한다
        - `OrderItems` 를 생성한다
        -  `VisitDate` 를 생성한다
        - `Order` 객체를 생성한다

- `OrderParser`: 사용자 입력 문자열을 trim 하고, ',' 로 스플릿하고, '-' 로 스플릿해서 '메뉴이름, 주문수량' map을 생성한다

## B. 이벤트
- `EventResult`: 최종 결과물
    - 필드
        - `Benefits benefits`
        - `Badge badge`
        - `int finalPaymentAmount`
- `Benefit`: 혜택의 내용을 표현
    - 필드
        - `BenefitType type`
        - `String eventName`
        - `int amount`
    - 메서드
        - `int getAmount()`: 총 혜택 금액
        - `int getDiscountAmount()`: 실 결제 금액
- `Benefits`: 최종 혜택 모음
    - 필드
        - `List<Benefit> items`
    - 메서드
        - `int calculateTotalDiscountAmount()`
        - `int calculateTotalBenefitAmount()`
        - `List<Benefit> getItems()`
- `EventPolicy`: interface, 이벤트 적용 조건과 결과를 구현
    - `boolean isSatisfiedBy(Order order)`
    - `Benefit apply(Order order)`
        - `DdayEventPolicy`
        - `WeekdaysEventPolicy`
        - `WeekendEventPolicy`
        - `SpecialdayEventPolicy`
        - `GiftEventPolicy`
- `EventManager`: `Order` 객체를 받아 이벤트 혜택을 분석하고 결과를 생성
    - `Benefits applyAll(Order order)`

- `BenefitCategory`: enum, 혜택의 형태, 비용 차감, 샴페인 증정
    - 필드
        - `DEDUCTION`
        - `PRESENTATION`
    - 메서드
        - `boolean isDeductible()`
- `BenefitType`: enum, 혜택의 타입, 할인, 증정
    - 필드
        - `DISCOUNT("할인", BenefitCategory.DEDUCTION)`
        - `GIFT("증정", BenefitCategory.PRESENTATION)`
    - 메서드
        - `boolean isDiscount()`
- `Badge`
    - 필드
        - `STAR("별", 5_000)`
        - `TREE("트리", 10_000)`
        - `SANTA("산타", 20_000)`
        - `NONE("없음",0)`


# 2. Application Layer
## A. Service
- `ChrismasEventService`: 요청을 받고 도메인을 이용해 결과를 만들 책임
    - `Order createOrder()`

## B. data
- `MenuInitializer`: 메뉴 엔티티를 초기화하고 레포지토리에 저장
    - 필드
        - `CsvReader csvReader`
        - `MenuRepository menuRepository`
    - 메서드
        - `void init()`

## C. Dto
- `OrderRequestDto`: 예약 날짜, 메뉴와 개수 운반

# 3. Presentation Layer
- `InputView`: 사용자에게 입력을 받기 위한 작업을 처리한다
    - 입력 받기 위한 프롬프트 출력의 책임
    - 아주 기초적인 입력값 검증 책임 (ex) 숫자를 기대할 경우 parseInt 등으로 검증해서 반환)
- `OutputView`: 사용자에게 결과를 출력한다
- `ChrismasEventController`: 프로그램 흐름을 컨트롤하고 요청 dto를 작성할 책임

# 4.  Infra Layer

## A. 레포지토리

- `MenuRepository`: 미리 정해진 가게 `Menu` 들을 저장하고 이를 조회, 반환한다
    - 필드: `List<Menu> menus`
    - 메서드: `Menu findByName(String menuName)`
