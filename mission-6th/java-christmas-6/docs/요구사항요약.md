# 요구사항 요약

## 도메인

- [ ] 메뉴 리스트가 존재한다
    - [ ] 메뉴는 에피타이저, 메인, 디저트, 음료 로 나뉜다
    - [ ] 메뉴는 메뉴 이름과 가격으로 구성된다
- [ ] 12월 이벤트를 구현하는 서비스이다
    - [ ] 12월 이벤트 참여 고객의 5%가 내년 1월 새해 이벤트에 재참여하길 기대한다
- [ ] 12월 이벤트
    - [ ] 크리스마스 디데이 할인: 1일 부터 25일 까지
        - [ ] 1,000원으로 시작해서 날마다 100원 씩 증가
    - [ ] 평일 할인: 일, 월, 화, 수, 목
        - [ ] 디저트 메뉴를 메뉴 1개당 2,023원 할인
    - [ ] 주말 할인: 금, 토
        - [ ] 메인 메뉴를 메뉴 1개당 2,023원 할인
    - [ ] 특별 할인: 3, 10, 17, 24, 25, 31
        - [ ] 달력에 별이 있는 날은 총 주문 금액에서 1,000원 할인
    - [ ] 증정 이벤트: 할인 전 총주문 금액이 12만원 이상
        - [ ] 샴페인 1개 (25,000원) 증정
    - [ ] 디데이 할인을 제외한 이벤트는 12월 내내 적용된다
- [ ] 총 혜택 금액의 합에 따라 이벤트 배지를 부여한다
    - [ ] 5천원 이상이면 별
    - [ ] 1만원 이상이면 트리
    - [ ] 2만원 이상이면 산타
- [ ] 주문 조건 및 이벤트 적용 조건
    - [ ] 총 주문 금액이 10,000원 이상이어야 이벤트가 적용된다
    - [ ] 음료만 주문할 수 없다
    - [ ] 종류에 상관없이 모든 메뉴는 한 번에 최대 20개까지만 주문할 수 있다

## 입출력

- [ ] 최종 출력 결과
    - [ ] 방문할 날짜
    - [ ] 주문 메뉴
    - [ ] 할인 전 총주문 금액
    - [ ] 증정 메뉴
    - [ ] 혜택 내역
    - [ ] 총 혜택 내역
    - [ ] 할인 후 예상 결제 금액
    - [ ] 12월 이벤트 배지
- [ ] 모든 에러 메시지에는 "[ERROR]" prefix 가 붙는다
- [ ] 방문 날짜는 1 이상 31 이하의 숫자 이다
    - [ ] 에러 메시지는 "유효하지 않은 날짜입니다. 다시 입력해 주세요." 이다
- [ ] 고객에게 주문할 메뉴와 개수를 입력 받는다
    - [ ] 양식은 "메뉴명-주문수량" 형식을 따른다
    - [ ] 주문 개수는 1 이상의 숫자 이다
    - [ ] 메뉴판에 없는 메뉴를 주문할 수 없다
    - [ ] 중복 메뉴를 입력할 수 없다
    - [ ] 에러 메시지는 "유효하지 않은 주문입니다. 다시 입력해 주세요." 이다
- [ ] 주문 메뉴의 출력 순서는 제한이 없다
- [ ] 총 혜택 금액 = 할인 금액의 합계 + 증정 메뉴의 가격
- [ ] 할인 후 예상 결제 금액 = 할인 전 총주문 금액 - 할인 금액
- [ ] 증정 메뉴나 혜택 내역이 없다면 "없음" 으로 표시한다

## 프로그래밍

- [ ] 3항 연산자 금지
- [ ] else 금지
- [ ] switch/case 금지
- [ ] 함수의 길이는 15라인을 넘지 않는다
- [ ] 도메인 로직에 단위 테스트 구현
- [ ] 다양한 에러 처리 유형을 명시한다
