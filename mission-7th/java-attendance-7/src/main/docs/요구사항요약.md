# 요구사항 요약
- 기능 목록을 만들고 기능 단위로 커밋하는 방식으로 진행한다
- 반드시 우테코 계정을 협력자로 초대해야 한다
- 시험 종료 이후에는 추가 푸시를 허용하지 않는다

- [ ] 우테코 출석 시스템을 만든다
- [ ] 출석 확인은 시스템에 출석 데이터가 저장된 시간을 기준으로 한다
- [ ] 시간은 24시간 형식을 사용한다. "22:30"
- [ ] 우테코의 교육 시간은
    - [ ] 월요일 13:00 ~ 18:00
    - [ ] 화요일~금요일 10:00 ~ 18:00
    - [ ] 끝나는 시간은 쓰이지 않는 것 같다.
- [ ] 시작 시각으로부터
    - [ ] 5분 초과 시 지각
    - [ ] 30분 초과 시 결석
- [ ] 등교하지 않아 출석 기록이 없으면 결석
- [ ] 지각 3회 = 결석 1회
    - [ ] 결석 2회 이상 = 경고 대상자
    - [ ] 결석 3회 이상 = 면담 대상자
    - [ ] 결석 5회 초과 = 제적 대상자
- [ ] 캠퍼스 운영 시간은 매일 08:00 ~ 23:00
    - [ ] 캠퍼스 운영 시간 외에 출석하려는 경우 예외 처리
- [ ] 주말 및 공휴일에는 출석을 등록하지 못한다
- [ ] `attendances.csv` 파일에서
    - [ ] 크루 이름
    - [ ] 12월 출석 기록
- [ ] 프로그램은 사용자가 종료할 때가지 종료되지 않으며, 해당 기능을 수행한 후 초기 화면으로 돌아간다
    - [ ] 사용자가 잘못된 값을 입력하면 `[ERROR] ` prefix 와 함께 애플리케이션이 종료된다

- [ ] 출석 확인
- [ ] 출석은
    - [ ] 닉네임
    - [ ] 등교 시간 을 입력 받아 처리한다
    - [ ] 이미 출석한 경우, 다시 출석 확인할 수 없다

- [ ] 출석 수정
- [ ] 출석 수정은
    - [ ] 닉네임
    - [ ] 수정하려는 날짜
    - [ ] 등교 시간을 입력 받아 처리한다
    - [ ] 수정 성공 시 수정 전과 후를 출력한다

- [ ] 크루별 출석 기록 확인
    - [ ] 닉네임을 입력받아 처리한다
    - [ ] 출석, 지각, 결석 횟수를 출력한다
    - [ ] 크루의 상태를 출력한다

- [ ] 제적 위험자 확인
    - [ ] 조회 전날까지의 기록으로 판단한다
    - [ ] 제적 대상자, 면담 대상자, 경고 대상자 순으로 정렬한다
    - [ ] 지각 + 결석 횟수로 내림차순 한다
    - [ ] 값이 같으면 이름으로 오름차순 한다


# 시나리오 정리
## 초기화
- 애플리케이션이 실행되고 csv 파일을 읽어 크루 와 그에 해당하는 출석 기록을 초기화


## 출석 확인
- 사용자에게 닉네임과 등교 시간을 입력 받는다

초안
- `Service` 는 `대상1` 에게 `닉네임` 을 넘겨주며 해당 `Crew` 가 있는지 조회를 요청한다
    - `대상1` 는 자신이 가진 `List<Crew>` 를 순회하며 해당 닉네임과 일치하는 대상이 있는지 찾아 넘겨준다. 리턴 값은 `Crew` 에 옵셔널. stream 사용
- `Service` 는 `Crew` 옵셔널을 확인해 null 이면 예외를 던진다
- `Service` 는 `Crew` 가 존재함을 확인하고 출석확인(등록) 작업을 한다
- `Service` 는 `등교 시간` 으로 지각인지 결석인지 체크한다
- `Service` 는 `CampusTime` 에게 `등교 시간` 을 넘겨주며 캠퍼스 시간 과의 차이 계산을 요청한다
    - `CampusTime` 는 자신이 가진 `기준` 으로 등교 시간 차이를 계산해 int 값을 리턴한다
- `Service` 는 `AttendanceStatus` 에게 `시간 차이` 을 넘겨주며 `지각, 결석 여부` 판별을 요청한다
    - `attendanceStatus` 는 자신이 가진 `기준` 으로 등교 시간의 상태를 판별해 `Attendance`을 리턴한다
- `Service` 는 `Attendance` 와 함께 `Crew` 를 만들고 `Crews` 를 만들어 반환한다

실제 구현
- Service 는 가지고 있는 Crews 로부터 이름을 통해 Crew 를 찾는다
- Service 는 찾아낸 Crew 에게 등교 시간을 넘겨주며 출석 기록 추가를 요청한다
    - Crew 는 StudyTime 에게
      이후 작성 필요

# 도메인

- `Crew` : 크루 한명을 표현한 객체, 이름과 스스로의 출석 기록을 가지고 출석 기록을 조작한다
    - 필드
        - `String nickName`
        - `List<Attendance> attendLog`
    - 메서드
        - `boolean findByName(String target)`
        - `void addAttendLog(LocalDateTime targetTime)`
- `Crews`: `Crew` 의 일급 컬렉션, 크루들 목록을 가지고 이름을 통해 해당 크루의 기록을 조회할 수 있다
    - 필드
        - `List<Crew> crews`
    - 메서드
        - `Crew findByName(String target)`
- `Attendance`
    - `AttendanceStatus status`: Enum, 지각, 결석, 출석(정상) 상태를 표현하며 운영 시간 대비 몇분 차이 나는지에 따라 알맞은 상태 값을 반환한다
        - ABSENT, LATE, ATTENDACE
    - `LocalDate date`
    - `LocalTime time`
- `StudyTime`: 캠퍼스의 수업 시간을 표현하며 등교 시간이 수업 시작으로부터 얼마나 차이 나는지 계산한다
    - `MONDAY`, `TUESDAY`...
    - 요일별 수업 시간을 가진다
    - `StudyTime findBy(LocalDateTime target)`
    - `int calculateDifferent(LocalTime target)`
